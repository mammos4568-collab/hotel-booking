# หลังบ้าน (เจ้าของโรงแรม / ผู้ดูแลระบบ)

หน้าเว็บ `/admin` · API `/api/admin/*` · โค้ด `server/src/modules/admin/` + `client/src/pages/admin/`
(เดิมเป็นงานของเพื่อน — ผู้ใช้สั่งให้ทำเองเมื่อ 22 ต.ค. 2569 **แจ้งเพื่อนด้วย** ไฟล์ใน `modules/admin/`, `pages/admin/` เปลี่ยนหมดแล้ว)

## บทบาท (`users.role`)

| | ลูกค้า (`user`) | เจ้าของโรงแรม (`owner`) | ผู้ดูแลระบบ (`admin`) |
|---|---|---|---|
| เข้า `/admin` | ✗ | ✓ | ✓ |
| ภาพรวม / สถิติ | | เฉพาะโรงแรมตัวเอง | ทั้งระบบ |
| เพิ่ม/แก้โรงแรม ห้อง ปฏิทินราคา | | เฉพาะโรงแรมตัวเอง (`properties.owner_id`) | ทุกโรงแรม + ตั้งเจ้าของ |
| ดูการจอง + ยกเลิกให้ลูกค้า (คืนเงิน) | | เฉพาะโรงแรมตัวเอง | ทุกการจอง |
| ดูรีวิว | | เฉพาะโรงแรมตัวเอง (ลบไม่ได้) | ทุกรีวิว + ลบรีวิวที่ผิดกฎ |
| ผู้ใช้และสิทธิ์ · บันทึกการทำงาน | | ✗ | ✓ |

**ตั้ง admin คนแรก** — ไม่มี API ให้ตั้งตัวเอง (ไม่งั้นใครก็ตั้งตัวเองเป็น admin ได้) ต้องรันบนเครื่อง server:

```bash
# สมัครสมาชิกผ่านหน้าเว็บก่อน แล้ว
node --env-file=server/.env server/scripts/set-role.js <email> admin
node --env-file=server/.env server/scripts/set-role.js <email> owner --hotels=1,2   # เจ้าของ + ยกโรงแรมให้
# production (ใน container)
docker compose -f docker-compose.prod.yml --env-file .env.production exec app node server/scripts/set-role.js <email> admin
```

หลังจากนั้น admin ตั้งเจ้าของโรงแรมได้ที่เมนู "ผู้ใช้และสิทธิ์" และเลือกเจ้าของของแต่ละโรงแรมที่หน้าแก้ไขโรงแรม
(สิทธิ์ใหม่มีผลทันที ไม่ต้องล็อกอินใหม่ — `requireAuth` อ่าน role จากฐานข้อมูลทุกคำขอ)

## ฐานข้อมูล — `db/05-admin.sql` (รันซ้ำได้)

- `CHECK (role IN ('user','owner','admin'))` บนตาราง `users`
- `properties.owner_id` → `users` (`ON DELETE SET NULL` = เจ้าของลบบัญชี โรงแรมกลับไปให้ admin ดูแล)
- `admin_audit_log(log_id, user_id, action, entity_id, detail JSONB, created_at)` — บันทึกการทำงาน

```bash
docker compose exec -T postgres psql -U agoda_admin -d agoda_db -f /docker-entrypoint-initdb.d/05-admin.sql
```

## จุดที่ต้องอธิบายได้ตอนพรีเซนต์

1. **ตรวจสิทธิ์ที่ server ทุกคำขอ ไม่ใช่แค่ซ่อนปุ่ม** — `requireRole('owner','admin')` ที่ `routes.js` แล้วทุกคำสั่งที่แตะโรงแรม/ห้อง/การจอง
   ผ่าน `ownedBy()` / `loadHotel()` / `loadRoom()` ใน `scope.js` → owner ยิง API ตรงไปที่โรงแรมคนอื่นก็ได้ 403
   (ตัวกรองเป็น SQL parameter `AND p.owner_id = $n` เสมอ ไม่ต่อ string)
2. **ลดจำนวนห้อง / ปิดขาย ไม่ทำให้จองเกิน** — `loadRoom(..., { lock: true })` = `SELECT ... FOR UPDATE OF r`
   ล็อก "แถวเดียวกับที่ตอนจองล็อก" (`lockRoomType`) แล้วค่อยนับห้องที่จองไปแล้ว → ระหว่างตรวจไม่มีการจองใหม่แทรกได้
   (ถ้าไม่ล็อก: admin เห็นว่าจองแล้ว 1 ห้องเลยลดเหลือ 1 แต่มีคนจองห้องที่ 2 แทรกพอดี = มีแขก 2 คนแต่เหลือ 1 ห้อง)
3. **หลังบ้านยกเลิกการจอง** ล็อกแถว `bookings` แบบเดียวกับฝั่งลูกค้า → ไม่ชนกับลูกค้าที่กำลังกดจ่ายเงิน
   ใช้ `cancelBooking()` ตัวเดียวกับลูกค้ายกเลิกเอง (`lib/bookings.js`) — จ่ายแล้วเปลี่ยนเป็นคืนเงินทั้งการจองและรายการชำระเงิน
4. **ต้องเหลือ admin อย่างน้อย 1 คน** — เปลี่ยนบทบาทตัวเองไม่ได้ และล็อกแถว admin ทุกคน (`FOR UPDATE`) ก่อนนับ
   ถ้า admin 2 คนลดสิทธิ์กันเองพร้อมกัน คนที่สองต้องรอ แล้วนับใหม่เห็นว่าเหลือคนเดียว → 409 (ทดสอบในข้อ 11 ของ `test/admin.js`)
   ลบบัญชี (`modules/privacy`) ใช้ลำดับล็อกเดียวกัน (แถว admin ก่อน) จึงไม่เกิด deadlock
5. **บันทึกการทำงานอยู่ใน transaction เดียวกับงาน** — งานสำเร็จ = มีบันทึก · งานล้ม (409/400) = ROLLBACK ทั้งคู่
   บันทึกเก็บแค่รหัสอ้างอิง ชื่อฟิลด์ที่แก้ และเหตุผล — ไม่เก็บข้อความรีวิวหรือข้อมูลลูกค้า (PDPA)
6. **ลบโรงแรม/ห้องที่เคยมีการจองไม่ได้** (409) เพราะประวัติการจองเป็นหลักฐานทางบัญชี → หยุดขายด้วยการตั้งจำนวนห้องเป็น 0
7. **สถิติ** — รายได้นับจาก `payments.status = 'Success'` (คืนเงินแล้วเป็น Refunded จึงไม่นับ) ตามวันจ่ายเงิน **เวลาไทย**
   · อัตราเข้าพักใช้ `nightlyRowsSql()` ตัวเดียวกับหน้าค้นหาและตอนจอง → ตัวเลข "ห้องที่ถูกจอง" ตรงกันทุกหน้า
   · ทุกส่วนไม่ขึ้นต่อกัน → `Promise.all` ยิง query พร้อมกัน
8. **ปฏิทินราคา** — `room_inventories` มี `UNIQUE (room_id, date)` → ตั้งราคาใช้ `INSERT ... ON CONFLICT DO UPDATE` (มีแถวแล้วแก้ทับ)
   ช่องที่ไม่ได้กรอกใช้ `COALESCE` คงค่าเดิม · "คืนค่าปกติ" = ลบแถวของวันนั้น (กลับไปใช้ราคา/จำนวนห้องของประเภทห้อง)

## PDPA

- เจ้าของโรงแรมเห็นชื่อ อีเมล เบอร์ และคำขอพิเศษของการจอง **เฉพาะโรงแรมตัวเอง** (ฐาน "ปฏิบัติตามสัญญา" — ต้องใช้เตรียมการเข้าพัก)
  · หน้าภาพรวมส่งแค่ชื่อผู้เข้าพัก · หน้ารีวิวแสดงชื่อแบบย่อเหมือนหน้าเว็บ
- ไฟล์ขอสำเนาข้อมูล (`/api/privacy/export`) มี `ownedHotels` และ `adminActions` (สิ่งที่ผู้ใช้ทำในหลังบ้าน)
- ลบบัญชี: โรงแรมที่ดูแลกลับไปให้ admin · บันทึกการทำงานยังอยู่แต่ไม่ผูกกับบัญชี · admin คนสุดท้ายลบบัญชีไม่ได้
- แจ้งไว้ในหน้า `/privacy` แล้ว

## ทดสอบ — `node server/test/admin.js` (เปิด server ก่อน · อ่าน `server/.env` เอง)

สมัครผู้ใช้ทดสอบ 4 คน ตั้ง admin ด้วยสคริปต์ แล้วลบข้อมูลทดสอบทั้งหมดตอนจบ — 72 ข้อ ผ่านทั้งหมด:

```
=== 1) สิทธิ์ ===                 ไม่ล็อกอิน 401 · ลูกค้า 403 · owner เข้าเมนูผู้ใช้/บันทึกไม่ได้ · เปลี่ยนบทบาทตัวเองไม่ได้
=== 2) โรงแรม + ประเภทห้อง ===   owner เป็นเจ้าของเอง · ตรวจข้อมูล (ลิงก์ javascript:, พิกัดไม่ครบคู่) · โรงแรมคนอื่น 403 ทุกเส้น
=== 3) ลูกค้าจองโรงแรมใหม่ ===    หน้าโรงแรมฝั่งลูกค้าเห็นห้องที่เพิ่ม · จอง + จ่ายได้จริง
=== 4) จำนวนห้อง + ปฏิทิน ===     ลดห้อง/ปิดขายต่ำกว่าที่จอง 409 · ตั้งราคาแล้วราคาที่ลูกค้าเห็นเปลี่ยน · เฉพาะวันเสาร์ · คืนค่าปกติ
=== 5) การจองในหลังบ้าน ===      owner อื่นไม่เห็น/ยกเลิกไม่ได้ · กรอง/ค้นหา · ยกเลิก + คืนเงิน · ลูกค้าเห็นสถานะยกเลิก
=== 6) ภาพรวม (สถิติ) ===         นับเฉพาะโรงแรมตัวเอง · ไม่นับเงินที่คืนแล้ว · อัตราเข้าพัก 1/60 ห้อง-คืน
=== 7) รีวิว ===                   owner ลบไม่ได้ · admin ลบได้ (ต้องมีเหตุผล)
=== 8) ลบโรงแรม/ห้อง ===          มีประวัติการจอง 409 · ไม่เคยจองลบได้
=== 9) เปลี่ยนบทบาท ===            owner → user ถอดจากโรงแรม + สิทธิ์หายทันที
=== 10) บันทึกการทำงาน ===        มีครบ · ไม่มีข้อความรีวิว · คำขอที่ถูกปฏิเสธไม่มีบันทึก
=== 11) admin สองคนลดสิทธิ์กันเองพร้อมกัน ===  สำเร็จคนเดียว ยังเหลือ admin 1 คน
```
