# หลังบ้าน (เจ้าของโรงแรม / ผู้ดูแลระบบ)

หน้าเว็บ `/admin` · API `/api/admin/*` · โค้ด `server/src/modules/admin/` + `client/src/pages/admin/`
(เดิมเป็นงานของเพื่อน — ผู้ใช้สั่งให้ทำเองเมื่อ 22 ต.ค. 2569 **แจ้งเพื่อนด้วย** ไฟล์ใน `modules/admin/`, `pages/admin/` เปลี่ยนหมดแล้ว)

## บทบาท (`users.role`)

| | ลูกค้า (`user`) | เจ้าของโรงแรม (`owner`) | ผู้ดูแลระบบ (`admin`) |
|---|---|---|---|
| เข้า `/admin` | ✗ | ✓ | ✓ |
| ภาพรวม / สถิติ | | เฉพาะโรงแรมตัวเอง | ทั้งระบบ |
| เพิ่ม/แก้โรงแรม ห้อง ปฏิทินราคา | | เฉพาะโรงแรมตัวเอง (`properties.owner_id`) | ทุกโรงแรม + ตั้งเจ้าของ |
| ดูการจอง + ยกเลิกให้ลูกค้า (คืนเงิน) | | เฉพาะโรงแรมตัวเอง | ทุกการจอง |
| ดูรีวิว | | เฉพาะโรงแรมตัวเอง (ลบไม่ได้) | ทุกรีวิว + ลบรีวิวที่ผิดกฎ |
| ผู้ใช้และสิทธิ์ · บันทึกการทำงาน | | ✗ | ✓ |

**ตั้ง/ถอด admin ได้ทางเดียว: สคริปต์บนเครื่อง server** — ไม่มี API ให้แตะสิทธิ์ admin เลย
(ถ้ามี: ใครก็ตั้งตัวเองเป็น admin ได้ หรือคนที่ได้บัญชี admin บนเว็บไป จะตั้งบัญชีตัวเองเป็น admin เพิ่มเป็นประตูหลัง
และถอด admin ตัวจริงออกได้ → ต้องมีสิทธิ์เข้าเครื่อง server / กุญแจ SSH ด้วยถึงจะทำได้)

```bash
# สมัครสมาชิกผ่านหน้าเว็บก่อน แล้ว
node --env-file=server/.env server/scripts/set-role.js <email> admin
node --env-file=server/.env server/scripts/set-role.js <email> user                # ถอด admin (ต้องเหลือ admin อย่างน้อย 1 คน)
node --env-file=server/.env server/scripts/set-role.js <email> owner --hotels=1,2   # เจ้าของ + ยกโรงแรมให้
# production (ใน container)
docker compose -f docker-compose.prod.yml --env-file .env.production exec app node server/scripts/set-role.js <email> admin
```

เมนู "ผู้ใช้และสิทธิ์" ในหน้าเว็บเปลี่ยนได้แค่ **ลูกค้า ↔ เจ้าของโรงแรม** (แถวของ admin เปลี่ยนจากหน้าเว็บไม่ได้)
และเลือกเจ้าของของแต่ละโรงแรมที่หน้าแก้ไขโรงแรม
(สิทธิ์ใหม่มีผลทันที ไม่ต้องล็อกอินใหม่ — `requireAuth` อ่าน role จากฐานข้อมูลทุกคำขอ)

## จุดที่ต้องอธิบายได้ตอนพรีเซนต์

1. **ตรวจสิทธิ์ที่ server ทุกคำขอ ไม่ใช่แค่ซ่อนปุ่ม** — `requireRole('owner','admin')` ที่ `routes.js` แล้วทุกคำสั่งที่แตะโรงแรม/ห้อง/การจอง
   ผ่าน `ownedBy()` / `loadHotel()` / `loadRoom()` ใน `scope.js` → owner ยิง API ตรงไปที่โรงแรมคนอื่นก็ได้ 403
   (ตัวกรองเป็น SQL parameter `AND p.owner_id = $n` เสมอ ไม่ต่อ string)
2. **ลดจำนวนห้อง / ปิดขาย ไม่ทำให้จองเกิน** — `loadRoom(..., { lock: true })` = `SELECT ... FOR UPDATE OF r`
   ล็อก "แถวเดียวกับที่ตอนจองล็อก" (`lockRoomType`) แล้วค่อยนับห้องที่จองไปแล้ว → ระหว่างตรวจไม่มีการจองใหม่แทรกได้
   (ถ้าไม่ล็อก: admin เห็นว่าจองแล้ว 1 ห้องเลยลดเหลือ 1 แต่มีคนจองห้องที่ 2 แทรกพอดี = มีแขก 2 คนแต่เหลือ 1 ห้อง)
3. **หลังบ้านยกเลิกการจอง** ล็อกแถว `bookings` แบบเดียวกับฝั่งลูกค้า → ไม่ชนกับลูกค้าที่กำลังกดจ่ายเงิน
   ใช้ `cancelBooking()` ตัวเดียวกับลูกค้ายกเลิกเอง (`lib/bookings.js`) — จ่ายแล้วเปลี่ยนเป็นคืนเงินทั้งการจองและรายการชำระเงิน
4. **สิทธิ์ admin แตะได้จากเครื่อง server เท่านั้น** — API เปลี่ยนบทบาทรับแค่ `user`/`owner` · ตั้งใครเป็น admin หรือแตะบัญชี
   ที่เป็น admin → 403 (ตรวจหลังล็อกแถวผู้ใช้ `FOR UPDATE` → ไม่ชนกับสคริปต์ที่ตั้งคนเดียวกันเป็น admin พร้อมกัน)
   · **ต้องเหลือ admin อย่างน้อย 1 คน** บังคับที่ `set-role.js`: ล็อกแถว admin ทุกคน (`FOR UPDATE` เรียงตาม `user_id`) ก่อนนับ
   รันสคริปต์ถอด admin 2 คนพร้อมกัน คนที่สองต้องรอ แล้วนับใหม่เห็นว่าเหลือคนเดียว → ถูกปฏิเสธ (ทดสอบในข้อ 11 ของ `test/admin.js`)
   ลบบัญชี (`modules/privacy`) ใช้ลำดับล็อกเดียวกัน (แถว admin ก่อน เรียงตาม `user_id`) จึงไม่เกิด deadlock
5. **บันทึกการทำงานอยู่ใน transaction เดียวกับงาน** — งานสำเร็จ = มีบันทึก · งานล้ม (409/400) = ROLLBACK ทั้งคู่
   บันทึกเก็บแค่รหัสอ้างอิง ชื่อฟิลด์ที่แก้ และเหตุผล — ไม่เก็บข้อความรีวิวหรือข้อมูลลูกค้า (PDPA)
6. **ลบโรงแรม/ห้องที่เคยมีการจองไม่ได้** (409) เพราะประวัติการจองเป็นหลักฐานทางบัญชี → หยุดขายด้วยการตั้งจำนวนห้องเป็น 0
7. **สถิติ** — รายได้นับจาก `payments.status = 'Success'` (คืนเงินแล้วเป็น Refunded จึงไม่นับ) ตามวันจ่ายเงิน **เวลาไทย**
   · อัตราเข้าพักใช้ `nightlyRowsSql()` ตัวเดียวกับหน้าค้นหาและตอนจอง → ตัวเลข "ห้องที่ถูกจอง" ตรงกันทุกหน้า
   · ทุกส่วนไม่ขึ้นต่อกัน → `Promise.all` ยิง query พร้อมกัน
8. **ปฏิทินราคา** — `room_inventories` มี `UNIQUE (room_id, date)` → ตั้งราคาใช้ `INSERT ... ON CONFLICT DO UPDATE` (มีแถวแล้วแก้ทับ)
   ช่องที่ไม่ได้กรอกใช้ `COALESCE` คงค่าเดิม · "คืนค่าปกติ" = ลบแถวของวันนั้น (กลับไปใช้ราคา/จำนวนห้องของประเภทห้อง)
9. **รูปโรงแรม (สูงสุด 5 รูป ขนาดเท่ากันทุกรูป)** — ดูหัวข้อ "รูปโรงแรม" ด้านล่าง
10. **อนุมัติโรงแรม + กรองคำหยาบ** — ดูหัวข้อ "อนุมัติโรงแรม" ด้านล่าง

## อนุมัติโรงแรม — `db/08-hotel-approval.sql` · `lib/hotelApproval.js` · `lib/moderation.js`

1. **สถานะ** `properties.approval_status`: `pending` รอตรวจ · `approved` เผยแพร่ · `rejected` ไม่อนุมัติ/ระงับ
   · owner เพิ่มโรงแรม → `pending` · admin เพิ่มเอง → `approved` ทันที — **server ตั้งจาก role** แอบส่งสถานะมาก็ไม่มีผล
   · **อนุมัติครั้งเดียวตอนสร้าง**: อนุมัติแล้ว owner แก้ข้อมูลได้เลย (ข้อความทุกช่องยังผ่านตัวกรองคำหยาบ)
   · admin ระงับโรงแรมที่เผยแพร่อยู่ได้ตลอด (ต้องมีเหตุผล) → owner แก้แล้วบันทึก = ส่งตรวจใหม่ (`rejected` → `pending`)
   · ไฟล์ db เพิ่มคอลัมน์ด้วยค่าเริ่มต้น `approved` (โรงแรมเดิมยังเห็นตามปกติ) แล้วเปลี่ยนค่าเริ่มต้นเป็น `pending`
     → แถวใหม่ที่ไม่ระบุ = ต้องรออนุมัติเสมอ (ปลอดภัยไว้ก่อน)
2. **ซ่อนจากลูกค้าทุกช่องทาง ไม่ใช่แค่หน้าค้นหา** — `publicHotelSql()` อยู่ใน WHERE ของ: ค้นหา, หน้าโรงแรม (404),
   ปลายทางยอดนิยม, ขอราคา, **จอง (ตรวจหลังล็อกห้อง — ยิง API ด้วย roomId ตรงๆ ก็จองไม่ได้)**, รายการโปรด, ผู้ช่วยแนะนำที่พัก
   · การจองเดิมของโรงแรมที่ถูกระงับยังอยู่ครบ (ลูกค้าเปิดดู/ยกเลิกได้) แค่จองใหม่ไม่ได้
3. **อนุมัติ/ระงับล็อกแถวโรงแรม** (`FOR UPDATE`) + บันทึก `hotel.approve` / `hotel.reject` (พร้อมเหตุผล) ใน transaction เดียวกัน
   → ไม่ชนกับ owner ที่กำลังบันทึกแก้ไขพร้อมกัน · อนุมัติซ้ำ = 409
4. **ตัวกรองคำหยาบ 2 ระดับ** (ชื่อ, คำอธิบาย, ที่อยู่, เมือง, ชื่อ/คำอธิบาย/เตียงของห้อง)
   - **บล็อก** (`findProfanity`) — คำหยาบไทย (ตัดคำด้วย `Intl.Segmenter` เทียบทั้งคำ → "สัดส่วน" ไม่โดน), อังกฤษ (รวม `sh1t`, `f*ck`, `f u c k`),
     **ทับศัพท์**: อังกฤษเขียนไทย (`ฟัค`, `บิทช์` — ตรวจแบบมีอยู่ในข้อความ เพราะตัวตัดคำไม่รู้จัก) และไทยเขียนอังกฤษ (`kuay`, `ai sus`
     — เทียบทั้งคำ + ต่อคู่คำที่ถูกเว้นวรรค จึงไม่ติด Phuket / River Kwai / Mueang) · คำที่ตัวตัดคำหั่นผิดใช้ pattern เช่น `เชี่ย` ที่ไม่ตามด้วย `ว`
   - **เตือน admin** (`findSuspiciousWords`) — คำก้ำกึ่งที่อาจเป็นคำปกติ/ชื่อจริง: `sus`, `hee`, `mung` (ถั่วเขียว), `cock` (ไก่), `แม่ง` (แม่งาน), `กะหรี่` (แกงกะหรี่)
     → บันทึกได้ แต่ขึ้นป้าย "คำที่ควรตรวจ" ในรายการโรงแรมและตอนอนุมัติ (เฉพาะ admin เห็น)
5. หน้าเว็บ: แท็บสถานะ + จำนวนในรายการโรงแรม (รออนุมัติขึ้นก่อน) · แถบสถานะบนหน้าแก้ไข (owner เห็นเหตุผล · admin มีปุ่มอนุมัติ/ไม่อนุมัติ/ระงับ)
   · หน้าภาพรวมเตือน "มีโรงแรมรออนุมัติ N แห่ง" (`HotelApproval.jsx`, `HotelsPage.jsx`, `DashboardPage.jsx`)

## รูปโรงแรม — `db/07-hotel-images.sql` · `modules/admin/hotelImages.js` · `lib/hotelImages.js`

1. **เบราว์เซอร์ย่อรูปก่อนอัป** (`client/src/lib/imageResize.js` ไม่ลง library) — ครอปกลางภาพให้ได้สัดส่วน 3:2
   (กว้างเกินตัดซ้าย/ขวา · สูงเกินตัดบน/ล่าง เท่าๆ กัน) แล้ววาดลง `<canvas>` 1200×800 → ได้ JPEG ขนาดเท่ากันทุกรูป
   · วาดใหม่ = ข้อมูลแฝงในไฟล์ (EXIF เช่น พิกัด GPS, รุ่นกล้อง) หายไปด้วย · PNG พื้นโปร่งใสได้พื้นขาว
2. **server ไม่เชื่อหน้าเว็บ ตรวจซ้ำ** (`checkHotelImage()`) — ดู "เนื้อไฟล์" ไม่ดูนามสกุล: ต้องขึ้นต้นด้วย `FF D8` (JPEG)
   ปิดท้ายด้วย `FF D9` (ไฟล์ไม่ขาด) และอ่านกว้าง×สูงจาก segment SOF ใน header ต้องได้ 1200×800 พอดี · ไม่เกิน 1.5 MB
   → ยิง API ตรงด้วยไฟล์อื่น (SVG, รูปขนาดอื่น) ได้ 400 · หน้าเว็บยังบังคับสัดส่วนการแสดงผลด้วย CSS อีกชั้น
3. **อัปพร้อมกันก็ไม่เกิน 5 รูป** — ล็อกแถวโรงแรม (`loadHotel(..., { lock: true })` = `FOR UPDATE`) ก่อนนับรูป
   คำขอที่สองต้องรอจนคำขอแรก COMMIT แล้วนับใหม่ (ถ้าไม่ล็อก สองคำขอนับได้ 4 พร้อมกัน → ได้ 6 รูป หรือลำดับที่ 5 ซ้ำ)
   ฐานข้อมูลกันชั้นสุดท้ายด้วย `CHECK (position BETWEEN 1 AND 5)` + `UNIQUE (property_id, position)` (ทดสอบยิงพร้อมกัน 7 รูป → ได้ 5)
4. **สลับลำดับรูปในคำสั่งเดียว** — `UNIQUE` ตั้งเป็น `DEFERRABLE INITIALLY DEFERRED` = ตรวจตอน COMMIT
   (ปกติ PostgreSQL ตรวจทีละแถว สลับ 1↔2 จะชนกันเองระหว่างทาง) · ลบรูปแล้วเรียงลำดับใหม่ด้วย `ROW_NUMBER()` ให้ต่อกันเสมอ
5. **เก็บรูปในฐานข้อมูล (BYTEA)** — backup ด้วย `pg_dump` ได้ครบ ไม่ต้องมีโฟลเดอร์/volume แยก · ลบโรงแรม = รูปหายตาม (`ON DELETE CASCADE`)
   · ส่งไฟล์เป็นไบต์ดิบ (`Content-Type: image/jpeg` + `express.raw()`) ไม่ต้องแปลง base64 และไม่ต้องลง library รับไฟล์
6. **ลูกค้าโหลดรูปที่ `GET /api/hotels/images/:id`** — รูปไม่เคยถูกแก้ทับ (อัปใหม่ = id ใหม่) → `Cache-Control: immutable` 1 ปี
   · รูปปก (รูปลำดับแรก) ใช้ `hotelCoverSql()` ตัวเดียวในทุก query ที่แสดงรูปโรงแรม (ค้นหา, รายการโปรด, การจอง, checkout, หลังบ้าน)
   · ยังไม่มีรูปอัปโหลด = ใช้ลิงก์รูปเดิม (`properties.image_url`) → ข้อมูลตัวอย่างยังแสดงรูปได้เหมือนเดิม
7. หน้าโรงแรม: แกลเลอรีรูปใหญ่ + 4 รูปเล็ก · กดรูปหรือ "ดูรูปทั้งหมด" → ดูเต็มจอ (`PhotoLightbox.jsx` ปัด/ลูกศร/Esc) · มือถือกรอบ 3:2
8. **เลือกรูปได้ตั้งแต่หน้าเพิ่มโรงแรม** (กดเลือกจากเครื่อง หรือลากรูปมาวาง) — ตอนนั้นโรงแรมยังไม่มีรหัส อัปไปผูกยังไม่ได้
   จึงย่อรูปเก็บไว้ในเบราว์เซอร์ก่อน (`HotelPhotoDraft` แสดงตัวอย่างด้วย data URL) พอกด "เพิ่มโรงแรม" ได้รหัสแล้ว
   `uploadDraftPhotos()` อัป **ทีละรูปตามลำดับ** (ยิงพร้อมกัน = ลำดับตามคำขอที่ถึง server ก่อน รูปปกอาจสลับ)
   · บางรูปอัปไม่สำเร็จ → โรงแรมยังถูกสร้าง แล้วบอกให้เพิ่มรูปนั้นใหม่ในหน้าแก้ไข · ระหว่างย่อรูปปุ่มบันทึกกดไม่ได้
   · ลิงก์รูปจากเว็บอื่นพับไว้เป็นตัวเลือกสำรอง "ใช้ลิงก์รูปจากเว็บแทน" (ข้อมูลตัวอย่างยังใช้แบบนี้)

## ทดสอบ — `node server/test/admin.js` (เปิด server ก่อน · อ่าน `server/.env` เอง)

สมัครผู้ใช้ทดสอบ 4 คน ตั้ง admin ด้วยสคริปต์ แล้วลบข้อมูลทดสอบทั้งหมดตอนจบ — 76 ข้อ ผ่านทั้งหมด
(อนุมัติโรงแรม + คำหยาบ: `node server/test/hotel-approval.js` 56 ข้อ · รูปโรงแรม: `node server/test/hotel-images.js` 30 ข้อ):

```
=== 1) สิทธิ์ ===                 ไม่ล็อกอิน 401 · ลูกค้า 403 · owner เข้าเมนูผู้ใช้/บันทึกไม่ได้ · เปลี่ยนบทบาทตัวเองไม่ได้
=== 2) โรงแรม + ประเภทห้อง ===   owner เป็นเจ้าของเอง · ตรวจข้อมูล (ลิงก์ javascript:, พิกัดไม่ครบคู่) · โรงแรมคนอื่น 403 ทุกเส้น
=== 3) ลูกค้าจองโรงแรมใหม่ ===    หน้าโรงแรมฝั่งลูกค้าเห็นห้องที่เพิ่ม · จอง + จ่ายได้จริง
=== 4) จำนวนห้อง + ปฏิทิน ===     ลดห้อง/ปิดขายต่ำกว่าที่จอง 409 · ตั้งราคาแล้วราคาที่ลูกค้าเห็นเปลี่ยน · เฉพาะวันเสาร์ · คืนค่าปกติ
=== 5) การจองในหลังบ้าน ===      owner อื่นไม่เห็น/ยกเลิกไม่ได้ · กรอง/ค้นหา · ยกเลิก + คืนเงิน · ลูกค้าเห็นสถานะยกเลิก
=== 6) ภาพรวม (สถิติ) ===         นับเฉพาะโรงแรมตัวเอง · ไม่นับเงินที่คืนแล้ว · อัตราเข้าพัก 1/60 ห้อง-คืน
=== 7) รีวิว ===                   owner ลบไม่ได้ · admin ลบได้ (ต้องมีเหตุผล)
=== 8) ลบโรงแรม/ห้อง ===          มีประวัติการจอง 409 · ไม่เคยจองลบได้
=== 9) เปลี่ยนบทบาท ===            owner → user ถอดจากโรงแรม + สิทธิ์หายทันที
=== 10) บันทึกการทำงาน ===        มีครบ · ไม่มีข้อความรีวิว · คำขอที่ถูกปฏิเสธไม่มีบันทึก
=== 11) ตั้ง/ถอด admin ===         ผ่าน API → 403 ทั้งตั้งและถอด · สคริปต์ตั้งได้ · สคริปต์ถอด 2 คนพร้อมกัน สำเร็จคนเดียว เหลือ admin 1 คน
```
